대시보드 열기

뜨는 밈 키워드에서 서울의 장소를 스스로 추리고, 그 장소의 연령별 반응·생활인구·도로·대기질을 같은 시간축에 맞춰 보는 프로그램입니다. 처음이라면 위에서부터 순서대로 읽으세요. 체크리스트까지 따라 하면 설정이 끝납니다.

누가 무엇을 하나요

Claude가 자료를 대신 모아 주나요?

아니요. Claude는 대화할 때만 작동하고, 대화창을 닫으면 아무것도 실행하지 않습니다. 기관 사이트에 대신 로그인하거나 접속할 권한도 없습니다. Claude는 이 프로그램을 만들고, 막혔을 때 함께 고치는 역할입니다.

Claude에 게시된 페이지(claude.ai/artifact/…)가 모아 주나요?

아니요. Claude 게시 페이지는 보안 정책상 외부 사이트에 접속할 수 없어서 데모 보기, 자료 파일 열기, CSV 분석만 됩니다. 화면을 미리 보거나 다른 사람에게 보여 주는 용도입니다.

그럼 실제로는 누가 모으나요?

GitHub에 올린 수집기가 GitHub 서버에서 30분마다 스스로 실행되며 모읍니다. 결과는 내 github.io 사이트에 자동으로 올라갑니다.

매번 로그인하거나 버튼을 눌러야 하나요?

아니요. 처음 한 번 인증키를 받아 GitHub에 등록하면 그 뒤로는 할 일이 없습니다. 인스타그램에 60일짜리 토큰을 쓴 경우만 만료 전에 바꿔 줘야 합니다.

내 컴퓨터를 켜 둬야 하나요?

GitHub 방식이면 필요 없습니다. 내 컴퓨터에서 수집기를 돌리는 방식을 고른 경우에만 켜 둬야 합니다.

아무것도 설정하지 않으면요?

수집기가 돌 곳이 없어 자동 수집은 되지 않습니다. GitHub만 켜고 인증키를 넣지 않으면 구글 급상승 검색어 하나만 모입니다.

인증키는 왜 내가 직접 받아야 하나요? 남에게 보이나요?

기관마다 본인 가입과 약관 동의가 필요해서 대신 받을 수 없습니다. 모두 무료입니다(구글 지도만 결제 계정 등록 필요). GitHub Secrets에 넣은 값은 저장소 주인도 다시 볼 수 없고, 화면이나 자료 파일에 들어가지 않습니다.

설정 체크리스트

인증키부터 신청해 두면 승인을 기다리는 동안 GitHub 설정을 할 수 있습니다. 표시는 이 브라우저에 저장됩니다.

    인증키 받기

    받은 키는 GitHub 저장소 › Settings › Secrets and variables › Actions › New repository secret에서 아래 이름 그대로 등록합니다. 앞뒤 공백 없이 붙여넣으세요.

    서울 실시간 도시데이터 기본 SEOUL_API_KEY

    1. 서울 열린데이터광장(data.seoul.go.kr)에 가입하고 로그인
    2. ‘서울시 실시간 도시데이터’를 검색해 인증키 신청 (승인 하루 안팎)
    3. 같은 페이지의 ‘주요 장소 목록(코드 포함).xlsx’를 받아 두면 장소 이름을 확인할 때 편합니다.

    이 키 하나로 추적 장소의 인구·연령·도로·날씨와 주요 장소 전체 스캔이 함께 켜집니다. 인증키마다 하루 호출 수가 제한됩니다.

    네이버 개발자센터 기본 NAVER_CLIENT_ID NAVER_CLIENT_SECRET

    1. developers.naver.com › Application › 애플리케이션 등록
    2. 사용 API에 ‘데이터랩(검색어트렌드)’와 ‘검색’ 둘 다 추가. 환경은 WEB, 서비스 URL은 http://localhost
    3. 등록 후 Client ID와 Client Secret 복사

    밈 키워드 발굴, 장소 찾기(지역 검색), 연령별 검색 추이, 블로그·뉴스 게시물 수가 모두 이 앱 하나로 돌아갑니다. 데이터랩은 하루 1,000회, 검색은 25,000회 한도이며 기본 설정 사용량은 그 안에 들어갑니다.

    에어코리아 대기오염정보 권장 AIRKOREA_API_KEY

    1. 공공데이터포털(data.go.kr)에 가입하고 로그인
    2. ‘한국환경공단_에어코리아_대기오염정보’ 활용신청 (자동 승인, 실제 작동까지 1~2시간)
    3. 마이페이지 › 데이터활용 › 오픈API에서 일반 인증키(Decoding) 복사. Encoding 키를 넣어도 수집기가 알아서 처리합니다.

    유튜브 권장 YOUTUBE_API_KEY

    1. console.cloud.google.com에서 새 프로젝트 만들기
    2. API 및 서비스 › 라이브러리 › ‘YouTube Data API v3’ 사용 설정
    3. 사용자 인증 정보 › 사용자 인증 정보 만들기 › API 키. 키의 API 제한사항에서 YouTube Data API v3만 허용하는 것을 권장합니다.

    무료 하루 할당량 10,000 단위 중 기본 설정은 약 7,700 단위를 씁니다.

    구글 지도·인스타그램·X는 SNS·지도·게시물에서 설명합니다.

    자동 수집 켜기

    A. GitHub (권장, 약 15분, 무료)

    1. 저장소 만들기 github.com 가입 › 오른쪽 위 + › New repository. 이름 예: meme-pulse. Public으로 만듭니다(무료 GitHub Pages는 공개 저장소에서 작동합니다. 올라가는 것은 공공 자료 집계뿐이고 인증키는 비밀로 넣습니다).
    2. 파일 올리기 새 저장소 화면의 ‘uploading an existing file’을 누르고, 압축을 푼 폴더 안의 내용 전체를 끌어다 놓은 뒤 Commit changes. 숨김 폴더 .github이 안 보이면 윈도우 탐색기 › 보기 › 숨긴 항목, 맥 Finder는 Cmd + Shift + .을 누르세요. 올린 뒤 저장소에 .github/workflows/collect.yml이 있는지 꼭 확인합니다.
    3. 쓰기 권한 Settings › Actions › General › Workflow permissions를 ‘Read and write permissions’로 바꾸고 Save.
    4. 인증키 등록 Settings › Secrets and variables › Actions › New repository secret에 받은 키를 이름 그대로 하나씩 추가합니다.
      SEOUL_API_KEY기본
      NAVER_CLIENT_ID, NAVER_CLIENT_SECRET기본
      AIRKOREA_API_KEY권장
      YOUTUBE_API_KEY권장
      GOOGLE_MAPS_API_KEY, IG_USER_ID, IG_ACCESS_TOKEN, X_BEARER_TOKEN선택
    5. 첫 수집 Actions 탭 › 왼쪽 ‘Meme Pulse 자동 수집’ › Run workflow. 1~2분 뒤 초록 체크가 뜨면 성공입니다.
    6. 사이트 켜기 Settings › Pages › Source: Deploy from a branch › Branch: gh-pages, 폴더 / (root) › Save. 1~3분 뒤 위쪽에 주소가 나옵니다(예: https://아이디.github.io/meme-pulse/).
    7. 즐겨찾기 그 주소를 휴대폰·PC에 즐겨찾기하면 끝입니다. 설명서는 같은 주소 뒤에 guide.html을 붙이면 열립니다.

    GitHub 예약 실행은 붐비는 시간에 몇 분~수십 분 늦을 수 있고, 화면의 ‘자료 연결 상태’에 그대로 표시됩니다. 저장소에 60일 동안 변경이 없으면 GitHub가 예약 실행을 멈춥니다. 멈추면 Actions 탭에서 Enable workflow를 누르세요. config.json을 가끔 고쳐 저장하는 것만으로도 막을 수 있습니다.

    B. 내 컴퓨터에서 돌리기

    1. 파이썬 3.8 이상 설치 (python.org, 설치할 때 ‘Add to PATH’ 체크)
    2. collector/keys.env.example을 복사해 이름을 keys.env로 바꾸고 = 뒤에 인증키를 붙여 저장
    3. 압축을 푼 폴더에서 명령창을 열고 실행 (맥·리눅스는 python3)
      python collector/collect.py --check인증키·설정 확인
      python collector/collect.py한 번 수집
      python collector/collect.py --loop 60010분마다 계속 수집 (Ctrl+C로 종료)
    4. index.html을 더블클릭하면 data/data.js를 읽어 그립니다. --loop로 돌려 두면 화면도 새 자료를 자동으로 반영합니다.

    컴퓨터가 잠자기에 들어가면 수집도 멈춥니다. 연구실 서버라면 crontab에 */10 * * * * cd /경로/meme-pulse && python3 collector/collect.py를 넣는 방법도 있습니다.

    밈 키워드 → 장소 발굴

    네이버 앱이 연결되어 있으면 따로 켤 것이 없습니다. 3시간마다 다음 순서로 돕니다.

    1. 밈 키워드 모으기 ‘핫플, 요즘 뜨는, 팝업스토어, 성지순례, 인생샷 명소, 오픈런, 웨이팅 맛집, 챌린지 장소’ 같은 밈 성격 검색어로 최신 네이버 블로그 제목(유튜브 키가 있으면 유튜브 제목도)을 받아 단어와 두 단어 묶음을 셉니다. 최근 일주일 평소보다 2배 이상 많이 나온 말이 후보입니다. 흔한 말(후기, 추천, 카페 등)은 뺍니다. 여기에 최근 12시간의 구글 급상승 검색어와 직접 넣은 키워드(seed_keywords)를 더합니다. 제목 자체는 저장하지 않고 단어별 개수만 남깁니다.
    2. 장소로 풀기 키워드가 서울 주요 장소(약 120곳) 이름과 거의 같으면 그 장소로, 아니면 네이버 지역 검색의 첫 번째 서울 결과로 찾습니다. 주소의 동 이름이 주요 장소와 겹치면(예: 성수동 → 성수카페거리) 실시간 인구도 연결합니다. 서울에서 장소가 나오지 않는 말(유행어, 제품, 인물)은 버립니다. 한 번 찾은 결과는 7일 동안 다시 찾지 않습니다.
    3. 급상승 확인 키워드마다 최신 블로그 글 100개로 ‘최근 3일 하루 평균 ÷ 그 전 7일 하루 평균’을 계산해 2배 이상이면 한 번 포착으로 셉니다.
    4. 행사 제외 키워드나 장소 분류에 축제·페스티벌·콘서트·팬미팅·공연·박람회·사전예약·티켓 같은 말이 있으면 주최 측이 날짜와 정원을 정한 이벤트로 보고 추적하지 않습니다(‘행사’ 표시, 양성 대조군 후보).
    5. 추적 7일 안에 2번 이상 포착되거나 한 번에 5배 이상 뛰었거나 직접 입력한 키워드의 장소를 최대 8곳 추적합니다. 같은 장소를 가리키는 키워드는 하나로 묶고 연령별 검색 추이, 블로그·뉴스·유튜브 수, 그 구의 대기질 측정소 값을 자동으로 붙입니다. 14일 동안 다시 포착되지 않으면 빠집니다.
    6. 인구로 교차 확인 주요 장소 약 120곳을 3시간마다 훑어 평소 같은 요일·시간대보다 1.4배 이상 몰린 곳을 기록합니다. 키워드로 찾은 장소와 겹치면 ‘인구 확인’이 붙고 추적 순서에서 앞섭니다. 키워드 없이 인구만 늘어난 곳은 날씨·공휴일 때문일 수 있어 추적하지 않습니다.

    알아둘 점

    • 첫날은 비교할 ‘평소’가 없어 제목에 많이 나온 말을 우선 후보로 씁니다. 하루 이틀 지나면 진짜 급상승만 걸러집니다.
    • 지역 검색의 첫 결과를 쓰므로 가끔 엉뚱한 곳으로 풀립니다. ‘자동 발굴’ 탭의 ‘풀린 장소’를 보고 이상하면 그 말을 stopwords_extra에, 정확한 이름을 seed_keywords에 넣으세요.
    • 주요 장소 밖의 가게·팝업은 실시간 인구가 없어 게시물 수와 구 측정소 대기질로 봅니다.
    • 자동 발굴은 ‘밈일 가능성이 높은 장소’를 추려 주는 것까지입니다. 연구에 넣을지는 사람이 확인해 결정하고, 확정한 장소는 places에 도로변 측정소와 함께 옮겨 적으면 고정 장소가 됩니다.

    SNS·지도·게시물

    모두 공식 API로 받고 게시물의 개수·시각·반응 수 합만 저장합니다. 작성자 이름·계정·본문·사진은 저장하지 않아 대회 연구 윤리 심사에서도 설명하기 쉽습니다. 검색어는 각 추적 장소의 밈 키워드(고정 장소는 keyword_groups의 첫 검색어)를 씁니다.

    자료잡는 것설정
    네이버 블로그·뉴스 기본검색어별 하루 게시물 수. 3시간마다 최신 블로그 300개·뉴스 100개를 날짜별로 세고, 수집을 계속할수록 과거 날짜가 이어 붙습니다.네이버 앱의 사용 API에 ‘검색’ 추가
    유튜브 권장최근 7일 업로드 수와 그 영상들의 조회수 합(6시간마다)YOUTUBE_API_KEY
    구글 지도 결제 계정장소별 누적 리뷰 수의 하루 증가량(방문 반응의 대리 지표)같은 구글 클라우드 프로젝트에서 ‘Places API (New)’ 사용 설정, 결제 계정 연결, GOOGLE_MAPS_API_KEY. 예산 알림과 하루 할당량 제한을 걸어 두세요. google_places에 장소 검색 문장을 적습니다.
    인스타그램 선택해시태그별 1시간 게시물 수와 반응 수 합. 최근 24시간 게시물의 표본만 오고, 7일 동안 서로 다른 해시태그 30개까지입니다.아래 순서 참고
    X 유료검색어별 1시간 게시물 수게시물 수 조회가 되는 유료 이용, X_BEARER_TOKEN, x_queries
    인스타그램 연결 순서 (가장 복잡함)
    1. 인스타그램 계정을 프로페셔널 계정(크리에이터 또는 비즈니스)으로 전환 (연구용 새 계정 권장)
    2. 페이스북 페이지를 만들고 그 인스타그램 계정을 페이지에 연결
    3. developers.facebook.com › 내 앱 › 앱 만들기(유형: 비즈니스) › 제품에 Instagram Graph API(페이스북 로그인 방식) 추가
    4. 도구 › Graph API 탐색기에서 이 앱을 고르고 instagram_basic, pages_show_list, pages_read_engagement 권한으로 사용자 토큰 생성
    5. 탐색기에서 me/accounts?fields=instagram_business_account를 실행해 나온 id가 IG_USER_ID
    6. 토큰은 장기 토큰(60일)으로 바꾸거나, 비즈니스 설정 › 시스템 사용자에서 만료 없는 토큰을 만들어 IG_ACCESS_TOKEN에 넣습니다(자동 수집에는 시스템 사용자 토큰 권장).
    7. 해시태그 검색이 권한 오류로 막히면 앱 검수에서 ‘Instagram Public Content Access’를 신청해야 할 수 있습니다.

    해시태그는 instagram_hashtags에 # 없이 적습니다. 절대량이 아니라 같은 해시태그 안에서 시간에 따라 늘었는지로 해석하세요.

    화면 사용법

    처음 열었을 때

    자료가 없으면 ‘처음 오셨나요?’가 뜹니다. 먼저 둘러보기(데모), 자동 수집 연결하기(작동 구조와 연결 순서), 받아 둔 자료 열기 중에서 고르세요. 데모는 주황색 띠가 보이는 동안 만든 숫자입니다.

    자료 연결 상태

    자료원마다 마지막 관측 시각과 지연 여부를 막대로 보여 줍니다. 초록은 최신, 주황은 지연, 빨강은 오래됨·자료 없음. 문제가 있는 줄의 ‘연결 방법’/‘해결 방법’을 누르면 그 자료의 설정 순서와 오류에 맞는 해결책이 펼쳐지고, 위쪽 ‘기본 연결 n/6’ 막대가 다음 할 일을 알려 줍니다.

    탭하는 일
    연결 보기검색 관심도(연령별) → 생활인구(연령별 추정) → 도로 평균속도 → PM2.5 → 도로변 증분 ΔNO₂·ΔPM2.5 → 풍속 → 블로그·뉴스·유튜브 게시물 → 유튜브 조회수 → 인스타그램 → 구글 지도 새 리뷰 → 가져온 SNS CSV를 같은 시간축에 쌓습니다. 한 그래프에 커서를 올리면 모든 그래프의 같은 시각 값이 위쪽 줄에 나옵니다. 연령 색은 모든 그래프에서 같습니다(10대 분홍, 20대 주황, 30대 초록, 40대 파랑, 50대+ 보라, 전체 점선).
    자동 발굴지금 추적 중인 장소 밈 카드(누르면 그 장소 그래프로 이동), 키워드로 찾은 장소 표, 제목에서 갑자기 늘어난 말, 교차 확인용 인구 급증 장소, 구글 급상승 검색어.
    연령별 반응검색어별로 연령대마다 검색 정점, 상승 기울기, 방문 정점, 방문 변화, 지연, 민감도를 계산합니다. 최소 3주 자료가 필요합니다.
    시간 × 장소지표 하나를 골라 0~23시 × 장소 표로 평균을 봅니다. 평일/주말을 나눌 수 있습니다.
    현장 측정직접 잰 보행자·차량·센서 PM2.5를 넣으면 같은 시각의 공공 관측값을 붙이고 전·중·후 비교표를 만듭니다. SNS 게시물 수 CSV도 여기서 넣습니다.
    설정자료 위치, 새로고침 간격, 내 사이트 주소, 자료원별 성공·실패 기록, 장소 설정 확인.

    장소 선택 상자는 ‘키워드로 찾은 장소 밈’과 ‘고정 장소(현장 실험지)’로 나뉩니다. ‘이 장소의 연결 자료 CSV 저장’은 관측 시각마다 인구·도로·대기·그날 검색 지수·게시물 수를 한 줄로 묶어 엑셀용으로 저장합니다.

    현장 측정 CSV

    ‘현장 측정’ 탭의 ‘양식 CSV 저장’으로 양식을 받아 엑셀에서 채운 뒤 CSV(쉼표로 분리, UTF-8)로 저장해 불러옵니다. 붙여넣기도 됩니다. 불러온 기록은 그 브라우저에만 보관되니 원본 CSV는 따로 보관하세요.

    열 이름내용예
    date날짜2026-10-10
    site장소 id 또는 이름worldcup, 서울숲, 월드컵공원
    phase전 / 중 / 후중
    slot슬롯T1 ~ T4
    start슬롯 시작 시각16:40
    rep반복 번호1, 2, 3
    pedestrians5분 보행자 수85
    vehicles5분 차량 수42
    pm25_sensor휴대 센서 PM2.5 (㎍/㎥)21
    note메모 (선택)일몰 40분 전

    같은 날짜·장소·단계·슬롯의 반복값을 묶어 중앙값과 범위를 내고, 슬롯 시작 15분 뒤에 가장 가까운 도시데이터 관측(±40분)과 같은 시각의 측정소 1시간값(±70분)을 붙입니다. SNS 게시물 CSV는 time, place, platform, count, keyword 열로 넣습니다.

    지표 계산 방법

    생활인구(최소 + 최대) ÷ 2
    연령별 추정 인구생활인구 × 해당 연령 비율 ÷ 100 (10대 = 10대 비율, 50대+ = 50·60·70대 합, 0~9세 제외)
    도로변 증분같은 시각 도로변 측정소 − 도시대기 측정소. ΔNO₂는 ppb(ppm × 1000). 배경 농도와 국외 유입이 빠지므로 지역 교통 기여를 봅니다. NO₂가 교통에 더 민감해 1차 지표로 권합니다.
    블로그 급상승최근 3일 하루 평균 글 수 ÷ 그 전 7일 하루 평균
    인구 평소 대비지금 인구 ÷ 최근 4주 같은 평일/주말·앞뒤 1시간의 인구 중앙값(최근 24시간 제외)
    검색 정점선택 기간(최소 3주) 안에서 지수가 가장 높은 날
    상승 기울기정점 전 7일간 하루 평균 증가량
    방문 정점검색 정점 3일 전 ~ 14일 뒤 사이 해당 연령 추정 인구의 일평균이 가장 높은 날
    방문 변화방문 정점 일평균 ÷ 기준선 − 1 (기준선 = 기간 첫 7일 중앙값)
    지연방문 정점 − 검색 정점 (일)
    민감도방문 변화(%) ÷ 검색 증가(%)

    네이버 검색 지수는 연령대마다 따로 최댓값을 100으로 맞춘 값이라, 연령대끼리는 높이가 아니라 언제 오르고 얼마나 가파른지를 비교해야 합니다.

    설정 바꾸기 (collector/config.json)

    장소를 따로 적지 않아도 됩니다. GitHub에서 파일을 열고 연필 아이콘으로 고친 뒤 Commit하면 다음 수집부터 반영됩니다. JSON은 쉼표·따옴표 하나만 틀려도 수집기가 멈추니, 고친 뒤 python collector/collect.py --check로 확인하면 안전합니다.

    알아둘 한계

    • 넣지 않은 방식 로그인을 흉내 내거나 차단을 우회해 인스타그램·X 화면을 긁는 것, 구글 지도·네이버 지도 웹페이지에서 방문자 리뷰 수나 ‘붐비는 시간’을 긁는 것. GitHub 같은 서버 주소는 가장 먼저 막혀 며칠 안에 수집이 끊기고, 이용약관 위반이라 계정이 정지될 수 있으며, 대회 심사에서 ‘공식 API, 집계값만’이라고 답할 수 있어야 연구 윤리 문제가 생기지 않습니다. 같은 신호를 공식 경로로 대신 잡습니다(네이버 지도 방문 반응 → 블로그 후기 수, 구글 지도 붐비는 시간 → 도시데이터 실시간 인구와 리뷰 증가량).
    • 연령 정보 어떤 SNS도 연령을 주지 않습니다. 연령별 반응의 주 자료는 네이버 데이터랩 연령별 검색 지수와 도시데이터 연령 비율입니다.
    • 자료 지연 에어코리아 1시간값은 보통 정시 10~30분 뒤에 나오고, 점검 중에는 비어 있을 수 있습니다. 검색 지수는 일 단위이며 당일 값은 다음 날 확정됩니다.
    • 인구 추정 도시데이터 인구는 통신 자료 기반 추정 범위이고 연령 비율은 반올림된 값입니다.
    • 인과 해석 상관이 보여도 날씨·요일·계절이 함께 움직였을 수 있습니다. 풍속 그래프와 평일/주말 구분을 함께 보고, 전·중·후를 같은 요일·같은 슬롯으로 짝지어 비교하세요.
