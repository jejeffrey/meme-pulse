 Meme Pulse 시작하기 가이드
 — 처음 받은 사람이 가장 먼저 읽는 문서 (브라우저용: guide.html, 자세한 내용: README.txt)
================================================================


1. 한 장으로 보는 작동 구조
----------------------------------------------------------------

   [서울시·에어코리아·네이버·유튜브·구글·인스타그램 공식 API]
                       │  (인증키로 접속)
                       ▼
   [수집기 collect.py]  ← GitHub 서버에서 30분마다 자동 실행
                       │  (내 컴퓨터가 꺼져 있어도 돎)
                       ▼
   [data/data.js 자료 파일]  ← 중복 정리, 60일 보관
                       │
                       ▼
   [내 Meme Pulse 사이트  https://내아이디.github.io/meme-pulse/]
      화면을 열어 두면 5분마다 새 자료를 자동 반영

   장소는 미리 정하지 않습니다. 수집기가 블로그·유튜브 제목과 급상승
   검색어에서 뜨는 밈 키워드를 찾고, 그 키워드가 가리키는 서울의 장소를
   스스로 추려 추적합니다. (README 3-1장)

   자료를 모으는 주체는 오직 ‘수집기’ 하나입니다.
   화면(사이트)은 수집기가 만든 파일을 읽어서 보여 주기만 합니다.


2. 자주 묻는 질문 — 누가, 언제, 무엇을 하나요?
----------------------------------------------------------------

 Q. Claude 가 자료를 대신 모아 주나요?
 A. 아니요. Claude 는 대화할 때만 작동하고, 대화창을 닫으면 아무것도
    실행하지 않습니다. 기관 사이트에 대신 로그인하거나 접속할 권한도
    없습니다. Claude 는 이 프로그램을 만들어 주고, 막혔을 때 고쳐 주는
    역할입니다.

 Q. 그럼 Claude 에 게시된 페이지(claude.ai/artifact/…)가 모아 주나요?
 A. 아니요. Claude 게시 페이지는 보안 정책상 외부 사이트에 접속할 수
    없습니다. 그래서 그 페이지에서는 데모 보기, 자료 파일 열기, CSV 분석만
    됩니다. 화면 모양을 미리 보거나 다른 사람에게 보여 주는 용도입니다.

 Q. 그럼 실제로는 누가 모으나요?
 A. GitHub 에 올린 수집기가 GitHub 서버에서 30분마다 스스로 실행되며
    모읍니다. 결과는 내 github.io 사이트에 자동으로 올라갑니다.

 Q. 매번 로그인하거나 버튼을 눌러야 하나요?
 A. 아니요. 처음 한 번만 인증키를 발급받아 GitHub 에 등록하면, 그 뒤로는
    아무것도 하지 않아도 됩니다. (예외: 인스타그램 60일 토큰을 쓰는 경우
    만료 전에 바꿔 줘야 합니다. 5장 참고)

 Q. 내 컴퓨터를 켜 둬야 하나요?
 A. GitHub 방식이면 필요 없습니다. 내 컴퓨터 방식(README 3장 2-B)을
    고른 경우에만 켜 둬야 합니다.

 Q. 아무것도 설정하지 않으면 어떻게 되나요?
 A. 수집기가 돌 곳이 없어서 자동 수집은 전혀 되지 않습니다.
    GitHub 만 켜고 인증키를 하나도 넣지 않으면 ‘구글 급상승 검색어’ 하나만
    모입니다(인증키가 필요 없는 유일한 자료).

 Q. 인증키는 왜 내가 직접 받아야 하나요?
 A. 기관마다 본인 명의 가입과 이용약관 동의가 필요하기 때문입니다.
    다른 사람이 대신 받을 수 없습니다. 모두 무료입니다(구글 지도만 결제
    계정 등록 필요, 사용량은 무료 범위 안).

 Q. 인증키가 다른 사람에게 보이나요?
 A. 아니요. GitHub ‘Secrets’ 에 넣은 값은 저장소 주인도 다시 볼 수 없고
    화면이나 자료 파일에도 들어가지 않습니다.


3. 무엇을 켜면 무엇이 모이나 — 세 단계
----------------------------------------------------------------

 [최소] GitHub + 서울 인증키 + 네이버 앱          약 30분 (+ 키 승인 대기)
   · 밈 키워드 → 장소 자동 발굴과 추적 (네이버 앱이 핵심)
   · 서울 주요 장소 약 120곳 인구 스캔으로 교차 확인
   · 추적 장소의 생활인구·연령 비율·혼잡도·도로속도·날씨·PM2.5
   · 연령대별 네이버 검색 추이 (연령별 반응 분석의 핵심)
   · 네이버 블로그·뉴스 게시물 수 (앱에 ‘검색’ API 도 추가할 것)
   · 구글 급상승 검색어

 [권장] 최소 + 에어코리아 + 유튜브                 +10분
   · 측정소 PM2.5·NO₂, 도로변 − 도시대기 증분 (교통 기여 지표)
   · 유튜브 업로드 수·조회수 (10·20대 밈 확산 경로)

 [선택] 권장 + 구글 지도 / 인스타그램 / X
   · 구글 지도 하루 새 리뷰 수 — 결제 계정 등록 필요
   · 인스타그램 해시태그 게시물 수 — 전문가 계정 + Meta 앱, 설정이 가장 복잡
   · X 게시물 수 — 유료

 연구에 꼭 필요한 것은 ‘권장’까지입니다. 선택 항목은 보조 지표입니다.


4. 설정 체크리스트 (순서대로 표시하며 진행)
----------------------------------------------------------------
 인증키부터 신청해 두면 승인을 기다리는 동안 GitHub 설정을 할 수 있습니다.

 [ ] 1. 서울 열린데이터광장 가입 → ‘서울시 실시간 도시데이터’ 인증키 신청
 [ ] 2. 공공데이터포털 가입 → ‘한국환경공단_에어코리아_대기오염정보’ 활용신청
 [ ] 3. 네이버 개발자센터 → 애플리케이션 등록
        사용 API: ‘데이터랩(검색어트렌드)’ 와 ‘검색’ 둘 다 추가
 [ ] 4. (권장) 구글 클라우드 → YouTube Data API v3 사용 → API 키
 [ ] 5. GitHub 가입 → 새 저장소(Public) → 압축 푼 파일 전부 올리기
        (.github 폴더가 빠지지 않았는지 꼭 확인)
 [ ] 6. 저장소 Settings > Actions > General
        → Workflow permissions: Read and write
 [ ] 7. Settings > Secrets and variables > Actions 에 받은 키 등록
        SEOUL_API_KEY / AIRKOREA_API_KEY / NAVER_CLIENT_ID /
        NAVER_CLIENT_SECRET / YOUTUBE_API_KEY
 [ ] 8. Actions 탭 → ‘Meme Pulse 자동 수집’ → Run workflow → 초록 체크 확인
 [ ] 9. Settings > Pages → Branch: gh-pages → Save → 사이트 주소 확인
 [ ] 10. 사이트 주소를 즐겨찾기 / Claude 게시 페이지의 설정 탭에도 입력

 각 단계의 화면별 설명: README.txt 3장(기본), 3-2장(유튜브·구글·인스타).


5. 설정 후 확인할 것
----------------------------------------------------------------
 첫날
   · 사이트 맨 위 ‘자료 연결 상태’ 막대가 초록(최신)인지 확인합니다.
     빨간 글씨가 있으면 그 문구가 원인입니다 → README 9장.
   · 장소 이름·측정소 이름 오류가 가장 흔합니다(config.json 수정).

 처음 1~3주 동안 비어 있어도 정상인 것
   · 자동 발굴의 ‘평소 대비 배율’: 같은 요일·시간대 기록이 3번 쌓여야 계산
   · 연령별 반응 표: 최소 3주 자료 필요
   · 블로그·유튜브 추이: 수집을 계속할수록 과거 날짜가 이어 붙음

 가끔 할 일
   · 한 달에 한 번 사이트를 열어 막대가 모두 초록인지 확인
   · 저장소에 60일간 변경이 없으면 GitHub 가 예약 실행을 멈춤
     → config.json 을 가끔 수정·저장하거나, 멈추면 Actions 탭에서 Enable
   · 인스타그램 60일 토큰을 쓴다면 만료 전에 IG_ACCESS_TOKEN 교체
     (만료 없는 시스템 사용자 토큰을 쓰면 필요 없음)
   · 새 장소나 검색어를 연구에 넣고 싶으면 config.json 수정


6. 이 프로그램이 하지 않는 것
----------------------------------------------------------------
 · 인스타그램·X·구글 지도·네이버 지도 화면을 로그인 흉내나 차단 우회로
   긁어 오는 것 (며칠 안에 차단되고, 약관 위반이며, 대회 연구 윤리 심사에
   불리함). 같은 신호를 공식 API 로 대신 잡습니다 → README 8장.
 · 게시물 작성자·본문·사진 저장. 개수·시각·반응 수 합 같은 집계값만 남깁니다.
 · 밈인지 아닌지의 최종 판단. 자동 발굴은 ‘평소보다 사람이 몰렸다’는
   신호까지만 주고, 원인(밈·날씨·공휴일·사고)은 사람이 확인합니다.


7. 막혔을 때
----------------------------------------------------------------
 이 가이드의 내용은 화면에도 들어 있습니다. 처음 열면 ‘처음 오셨나요?’ 안내가,
 연결한 뒤에는 ‘자료 연결 상태’ 각 줄의 ‘연결 방법’/‘해결 방법’과 위쪽
 ‘기본 연결 n/6’ 막대가 다음 할 일을 알려 줍니다.

 1) 사이트의 ‘자료 연결 상태’에서 빨간 줄의 ‘해결 방법’을 눌러 확인
 2) README.txt 9장 ‘문제가 생겼을 때’에서 같은 메시지 찾기
 3) 그래도 안 되면 GitHub Actions 의 빨간 X 실행 로그나 막힌 화면을
    캡처해서 Claude 에게 보여 주면 그 단계부터 함께 고칠 수 있습니다.
