================================================================
 Meme Pulse 사용 설명서
 장소 밈의 연령별 반응 × 생활인구 × 도로 × 대기질 실시간 연결 화면
================================================================

브라우저로 보기 편한 설명서는 guide.html 입니다. 처음이라면 ‘시작하기_가이드.txt’를 먼저 읽으세요. 누가 자료를 모으는지,
무엇을 한 번만 설정하면 되는지, 설정 체크리스트가 한 장에 정리되어 있습니다.
(화면에도 녹아 있습니다: 처음 열면 ‘처음 오셨나요?’ 안내가, 연결한 뒤에는
 ‘자료 연결 상태’의 각 줄에 그 자료의 연결·해결 방법이 나타납니다)

차례
 1. 이 프로그램이 하는 일
 2. 들어 있는 파일

 4. 화면 사용법
 5. 현장 측정 기록(CSV) 넣기
 6. 지표 계산 방법
 7. 장소·검색어·측정소 바꾸기
 8. 알아둘 한계
 9. 문제가 생겼을 때


----------------------------------------------------------------
1. 이 프로그램이 하는 일
----------------------------------------------------------------
두 부분으로 나뉩니다.

 (1) 수집기 (collector/collect.py)
     공공 API에서 자료를 받아 data/data.js 파일에 계속 쌓습니다.
       - 서울 실시간 도시데이터 : 장소별 생활인구(최소~최대), 연령·성별 비율,
                                  혼잡도, 주변 도로 평균속도, 기온·습도·풍속,
                                  그 장소의 PM2.5·PM10  (약 5~15분마다 갱신)
       - 에어코리아             : 측정소별 PM2.5·PM10·NO₂ 1시간값
                                  (도시대기 측정소와 도로변 측정소를 짝지어 비교)
       - 네이버 데이터랩        : 검색어 그룹의 연령대별 일 단위 검색 지수
                                  (밈이 연령마다 언제, 얼마나 빨리 퍼지는지 보는 핵심 자료)
       - 네이버 블로그·뉴스     : 검색어별 하루 게시물 수 (네이버 키로 함께)
       - 유튜브 (선택, 무료)    : 검색어별 최근 7일 업로드 수와 조회수
       - 인스타그램 (선택)      : 해시태그별 1시간 게시물 수 (공식 API 표본)
       - 구글 지도 (선택)       : 장소별 누적 리뷰 수 → 하루 새 리뷰 수
       - X (선택, 유료)         : 검색어별 1시간 게시물 수
       - 자동 발굴              : 장소를 미리 정하지 않습니다. 블로그·유튜브
                                  제목과 급상승 검색어에서 뜨는 밈 키워드를
                                  찾고, 그 키워드가 가리키는 서울의 장소를
                                  스스로 추려 추적합니다. 인구 급증으로
                                  교차 확인합니다. (3-1장)
     같은 장소·같은 관측 시각의 중복은 자동으로 합치고, 60일이 지나면 지우며,
     7일이 지난 자료는 1시간에 1건으로 줄여 파일이 커지지 않게 합니다.

 (2) 화면 (index.html)
     data/data.js 를 읽어 모든 자료를 같은 시간축에 겹쳐 보여 줍니다.
     화면을 열어 두면 5분마다(설정에서 변경 가능) 자동으로 다시 읽습니다.
     맨 위 ‘자료 연결 상태’에서 자료원마다 마지막 관측 시각과 지연 여부를
     바로 확인할 수 있습니다.

 자동 수집 방법은 두 가지입니다. 하나만 고르면 됩니다.
   A. GitHub (권장) : 내 컴퓨터를 꺼 두어도 30분마다 자동 수집되고,
                      웹 주소 하나로 휴대폰에서도 봅니다. 무료.
   B. 내 컴퓨터     : 연구실 PC나 서버에서 파이썬으로 계속 돌립니다.
                      10분 간격처럼 더 촘촘하게 모을 수 있습니다.

 화면은 두 곳에서 열 수 있습니다.
   - 내 Meme Pulse 사이트 (A 방식의 github.io 주소) : 자동 수집 자료가
     실시간으로 이어지는 본 화면입니다.
   - Claude 에 게시된 페이지 : 링크로 바로 열리는 같은 화면입니다. Claude
     게시 페이지는 보안 정책상 외부 사이트에서 자료를 읽어 올 수 없어서,
     여기서는 데모·자료 파일 열기·CSV 분석만 됩니다. 설정 탭에 내 사이트
     주소를 넣어 두면 화면 위에 바로 가는 링크가 생깁니다.

   파일로 보일 수 있습니다. 지우지 마세요.


----------------------------------------------------------------
3. 처음 설정하기
----------------------------------------------------------------

[0단계] 먼저 둘러보기 (1분)
  index.html 을 더블클릭 → ‘가상 데모로 둘러보기’를 누릅니다.
  주황색 띠가 보이는 동안은 만든 숫자입니다. 실제 관측이 아닙니다.
  화면 구성을 익힌 뒤 ‘데모 끄기’를 누르세요.

[1단계] 인증키 받기 (모두 무료, 하루~이틀 걸릴 수 있음)

  ① 서울 실시간 도시데이터  →  이름: SEOUL_API_KEY
     - 서울 열린데이터광장 (data.seoul.go.kr) 가입·로그인
     - 검색창에 ‘서울시 실시간 도시데이터’ 검색 → 인증키 신청
       (마이페이지 > 인증키 발급 에서 일반 인증키를 받아도 됩니다)
     - 받은 인증키 문자열을 복사해 둡니다.
     - 같은 페이지의 ‘주요 장소 목록(코드 포함).xlsx’ 를 내려받아 두세요.
       장소 이름을 이 목록과 글자 하나까지 똑같이 적어야 합니다.

  ② 에어코리아 대기오염정보  →  이름: AIRKOREA_API_KEY
     - 공공데이터포털 (data.go.kr) 가입·로그인
     - ‘한국환경공단_에어코리아_대기오염정보’ 검색 → 활용신청
       (자동 승인. 다만 실제로 작동하기까지 1~2시간 걸릴 수 있습니다)
     - 마이페이지 > 데이터활용 > 오픈API 에서 ‘일반 인증키(Decoding)’를
       복사합니다. Encoding 키를 넣어도 수집기가 알아서 처리합니다.

  ③ 네이버 데이터랩 검색어 트렌드  →  이름: NAVER_CLIENT_ID, NAVER_CLIENT_SECRET
     - 네이버 개발자센터 (developers.naver.com) 로그인
     - Application > 애플리케이션 등록
       · 사용 API: ‘데이터랩(검색어트렌드)’ 선택
       · 환경: WEB 설정, 서비스 URL 에는 http://localhost 입력
     - 등록 후 Client ID 와 Client Secret 을 복사합니다.
     - 하루 호출 한도가 있습니다(현재 1,000회). 수집기는 6시간마다 한 번만
       갱신하도록 되어 있어 검색어 그룹 20개 이하에서는 넉넉합니다.

  ④ (선택) X  →  이름: X_BEARER_TOKEN
     - X 개발자 포털에서 앱을 만들고 Bearer Token 을 받습니다.
     - 게시물 수 조회는 무료 등급에서 막혀 있어 유료 이용이 필요합니다.
       요금은 X 개발자 포털에서 확인하세요. 없어도 나머지는 모두 작동합니다.

[2-A단계] GitHub 로 자동 수집 켜기 (권장, 15분)

  1) github.com 가입 → 오른쪽 위 + → New repository
     - 이름 예: meme-pulse
     - Public 선택 (무료 GitHub Pages 는 공개 저장소에서 작동합니다.
       올라가는 것은 공공 자료 집계뿐이고, 인증키는 4)에서 비밀로 넣습니다)
     - Create repository
  2) 새 저장소 화면의 ‘uploading an existing file’ 을 누르고,
     압축을 푼 폴더 안의 내용 전체(index.html, collector 폴더, .github 폴더,
     data 폴더 등)를 끌어다 놓은 뒤 Commit changes.
     ※ .github 폴더가 안 보이면: 윈도우 탐색기 > 보기 > 숨긴 항목 체크,
       맥 Finder 에서는 Cmd + Shift + . (마침표)
     ※ 올린 뒤 저장소에 .github/workflows/collect.yml 이 있는지 꼭 확인하세요.
  3) Settings > Actions > General
     - Workflow permissions 를 ‘Read and write permissions’ 로 바꾸고 Save.
  4) Settings > Secrets and variables > Actions > New repository secret
     아래 이름 그대로, 값에 1단계에서 받은 키를 넣어 하나씩 추가합니다.
        SEOUL_API_KEY
        AIRKOREA_API_KEY
        NAVER_CLIENT_ID
        NAVER_CLIENT_SECRET
        X_BEARER_TOKEN          (선택)
        YOUTUBE_API_KEY         (선택, 3-2장)
        IG_USER_ID              (선택, 3-2장)
        IG_ACCESS_TOKEN         (선택, 3-2장)
        GOOGLE_MAPS_API_KEY     (선택, 3-2장)
  5) 상단 Actions 탭 → 왼쪽 ‘Meme Pulse 자동 수집’ → Run workflow
     1~2분 뒤 초록 체크가 뜨면 성공입니다. (빨간 X 이면 9장 참고)
  6) Settings > Pages
     - Source: Deploy from a branch
     - Branch: gh-pages, 폴더 / (root) → Save
     - 1~3분 뒤 위쪽에 사이트 주소가 나옵니다.
       예: https://내아이디.github.io/meme-pulse/
  7) 그 주소를 휴대폰·PC 즐겨찾기에 넣어 두면 끝입니다.
     이후 30분마다 자동으로 수집되고, 화면은 열어 둔 동안 5분마다 새 자료를
     반영합니다. 브라우저를 닫아 두어도 수집은 계속됩니다.

  알아둘 점
   - GitHub 예약 실행은 붐비는 시간에 몇 분~수십 분 늦을 수 있습니다.
     화면의 ‘자료 연결 상태’에 그대로 표시됩니다.
   - 저장소에 60일 동안 아무 변경이 없으면 GitHub 가 예약 실행을 멈춥니다.
     멈추면 Actions 탭에 안내가 뜨고, Enable 을 누르면 다시 시작합니다.
     config.json 을 가끔 수정해 저장하는 것만으로도 막을 수 있습니다.
   - 설정(config.json)을 바꾸려면 GitHub 에서 그 파일을 열고 연필 아이콘으로
     고친 뒤 Commit 하면 다음 수집부터 반영됩니다.

[2-B단계] 내 컴퓨터로 자동 수집 (GitHub 대신)

  1) 파이썬 3.8 이상 설치 (python.org, 설치 시 ‘Add to PATH’ 체크)
  2) collector/keys.env.example 을 복사해 이름을 keys.env 로 바꾸고,
     = 뒤에 인증키를 붙여 넣어 저장합니다.
  3) 압축을 푼 폴더에서 명령창(터미널)을 열고:
        python collector/collect.py --check        인증키·설정 확인
        python collector/collect.py                한 번 수집
        python collector/collect.py --loop 600     10분마다 계속 수집
     (맥·리눅스는 python 대신 python3)
  4) index.html 을 더블클릭하면 data/data.js 를 읽어 그립니다.
     --loop 로 돌려 두면 화면도 자동으로 새 자료를 반영합니다.
  5) 컴퓨터가 잠자기에 들어가면 수집도 멈춥니다. 연구실 서버에서는
     crontab 에 다음 한 줄을 넣는 방법도 있습니다.
        */10 * * * * cd /경로/meme-pulse && python3 collector/collect.py


----------------------------------------------------------------
3-1. 자동 발굴 — 밈 키워드에서 장소를 추리는 방법
----------------------------------------------------------------
 장소를 미리 정하지 않습니다. 수집기가 ‘요즘 뜨는 말’을 먼저 찾고, 그 말이
 가리키는 서울의 장소를 스스로 추려 추적합니다. 네이버 앱(데이터랩 + 검색)이
 연결되어 있으면 따로 켤 것이 없습니다. 3시간마다 돕니다.

 ① 밈 키워드 모으기 — 세 군데에서
    · 제목 급상승어: ‘핫플, 요즘 뜨는, 팝업스토어, 성지순례, 인생샷 명소,
      오픈런, 웨이팅 맛집, 챌린지 장소’ 같은 밈 성격 검색어(seed_queries)로
      최신 네이버 블로그 글 제목(유튜브 키가 있으면 유튜브 제목도)을 받아,
      단어와 두 단어 묶음이 몇 번 나오는지 셉니다. 최근 일주일 평소보다
      2배 이상 많이 나온 말이 후보입니다. ‘후기, 추천, 카페’ 같은 흔한 말은
      자동으로 뺍니다. 제목 자체는 저장하지 않고 단어별 개수만 남깁니다.
    · 구글 급상승 검색어: 최근 12시간 안에 올라온 한국 급상승 검색어.
    · 직접 입력: config.json 의 keyword_discovery › seed_keywords 에 적은 밈.
      꼭 봐야 할 밈은 여기에 넣으면 급상승 여부와 상관없이 바로 추적합니다.
 ② 장소로 풀기
    · 키워드가 서울 주요 장소(도시데이터 약 120곳) 이름과 거의 같으면 그 장소로.
    · 아니면 네이버 지역 검색으로 찾아 첫 번째 서울 결과를 씁니다
      (가게, 팝업, 공원 등 어떤 장소든). 주소의 동 이름이 주요 장소 이름과
      겹치면 그 주요 장소의 실시간 인구도 연결합니다(예: 성수동 → 성수카페거리).
    · 서울에서 장소가 나오지 않는 말(유행어, 제품, 인물 등)은 장소 밈이 아니므로
      버립니다. 한 번 찾은 결과는 7일 동안 다시 찾지 않습니다.
 ③ 급상승 확인
    키워드마다 최신 블로그 글 100개를 받아 ‘최근 3일 하루 평균 ÷ 그 전 7일
    하루 평균’을 계산합니다. 2배 이상이면 한 번 포착으로 셉니다.
 ④ 행사 제외
    키워드나 장소 분류에 축제·페스티벌·콘서트·팬미팅·공연·박람회·사전예약·
    티켓 같은 말이 있으면 주최 측이 날짜·정원을 정한 이벤트로 보고 추적하지
    않습니다(‘행사’ 표시, 양성 대조군 후보). 목록은 event_words 에서 바꿉니다.
 ⑤ 추적
    7일 안에 2번 이상 포착되거나(또는 한 번에 5배 이상 급상승) 직접 입력한
    키워드의 장소를 최대 8곳 골라 추적합니다. 같은 장소로 풀린 키워드는 한
    장소로 묶입니다. 추적 장소에는 자동으로 다음이 붙습니다.
      - 연령별 네이버 검색 추이, 블로그·뉴스·유튜브 게시물 수 (그 키워드로)
      - 실시간 인구·연령·도로·날씨 (서울 주요 장소와 연결된 경우)
      - 그 구의 에어코리아 도시대기 측정소 PM2.5·NO₂
    14일 동안 다시 포착되지 않으면 자동으로 빠집니다.
 ⑥ 인구로 교차 확인
    서울 주요 장소 약 120곳을 3시간마다 훑어 평소 같은 요일·시간대보다
    1.4배 이상 몰린 곳을 기록합니다. 키워드로 찾은 장소와 겹치면 ‘인구 확인’
    표시가 붙고 추적 순서에서 앞섭니다. 키워드 없이 인구만 늘어난 곳은 날씨나
    공휴일 때문일 수 있어 추적하지 않습니다(바꾸려면 discovery ›
    population_auto_track 을 true 로). 평소 대비 배율은 1~3주 뒤부터 계산됩니다.

 알아둘 점
  · 첫날은 비교할 ‘평소’가 없어 제목에 많이 나온 말을 우선 후보로 씁니다.
    하루 이틀 지나면 진짜 급상승만 걸러집니다.
  · 네이버 지역 검색은 첫 번째 결과를 쓰므로 가끔 엉뚱한 곳으로 풀립니다.
    ‘자동 발굴’ 탭의 ‘풀린 장소’를 보고 이상하면 stopwords_extra 에 그 말을
    넣거나, 정확한 이름을 seed_keywords 에 넣으세요.
  · 추적 장소가 서울 주요 장소 밖이면 실시간 인구는 없습니다. 이때는
    게시물 수와 구 측정소 대기질로 봅니다.
  · 자동 발굴은 ‘밈일 가능성이 높은 장소’를 추려 주는 것까지입니다.
    연구에 넣을지는 사람이 확인해 결정하세요. 확정한 장소는 config.json 의
    places 에 도로변 측정소와 함께 옮겨 적으면 고정 장소가 됩니다.


----------------------------------------------------------------
3-2. SNS·지도·검색어 게시물 수집
----------------------------------------------------------------
 모두 공식 API로 받고, 게시물의 ‘개수·시각·반응 수 합’만 저장합니다.
 작성자 이름·계정·본문·사진은 저장하지 않습니다(개인정보가 남지 않아
 KSEF/ISEF 연구 윤리 심사에서도 설명하기 쉽습니다).
 검색어는 config.json 의 keyword_groups(자동 발굴 장소 포함)에서 각 그룹의
 첫 번째 검색어를 씁니다. 다른 검색어를 쓰려면 그룹에 "buzz_query" 를 넣으세요.

 ① 네이버 블로그·뉴스 — 추가 비용 없음, 강력 추천
    3장에서 만든 네이버 애플리케이션 > API 설정 > 사용 API 에 ‘검색’을
    추가하고 저장하면 끝입니다(같은 Client ID/Secret 사용).
    3시간마다 검색어별 최신 블로그 글 300개, 뉴스 100개를 날짜순으로 받아
    하루 게시물 수를 셉니다. 인기 검색어는 300개가 며칠 치밖에 안 되므로,
    수집을 계속 돌릴수록 과거 날짜가 이어 붙어 긴 추이가 됩니다.
    하루 호출 한도(검색 API 25,000회)에 비해 사용량은 수백 회입니다.

 ② 유튜브 — 무료 (이름: YOUTUBE_API_KEY)
    - console.cloud.google.com → 새 프로젝트 만들기
    - API 및 서비스 > 라이브러리 > ‘YouTube Data API v3’ 사용 설정
    - API 및 서비스 > 사용자 인증 정보 > 사용자 인증 정보 만들기 > API 키
      (만든 키의 ‘API 제한사항’에서 YouTube Data API v3만 허용 권장)
    6시간마다 검색어별 최근 7일 영상 최대 50개의 업로드 날짜와 조회수를
    받습니다. 무료 하루 할당량 10,000 단위 중 검색 1번이 약 100 단위라
    검색어 그룹 15개 기준 하루 약 6,000 단위를 씁니다.

 ③ 구글 지도 리뷰 수 — 결제 계정 등록 필요 (이름: GOOGLE_MAPS_API_KEY)
    - 위 구글 클라우드 프로젝트에서 ‘Places API (New)’ 사용 설정
    - 결제 계정을 연결해야 작동합니다. 기본 설정(장소 3곳, 하루 1회)은
      한 달 100회 안팎이지만, 요금 기준은 Google Maps Platform 가격
      페이지에서 직접 확인하세요.
    - 사고를 막으려면 결제 > 예산 및 알림에서 예산 알림(예: 1,000원)을
      설정하고, API 할당량을 하루 50회 정도로 낮춰 두세요.
    장소는 config.json 의 google_places 에 검색 문장(예: "하늘공원 서울
    마포구")과 연결할 장소 id 를 적습니다. 첫 수집 때 찾은 장소를 계속
    씁니다. 화면에는 누적 리뷰 수의 하루 증가량이 나오며, 방문 반응의
    대리 지표로 씁니다(리뷰는 방문 후 며칠 뒤에 달리는 경향이 있습니다).

 ④ 인스타그램 해시태그 — 설정이 가장 복잡함 (이름: IG_USER_ID, IG_ACCESS_TOKEN)
    인스타그램은 공개 해시태그 검색을 ‘전문가 계정 + Meta 앱’으로만 엽니다.
    - 인스타그램 앱 > 설정 > 계정 유형 > 프로페셔널 계정(크리에이터 또는
      비즈니스)으로 전환 (연구용 새 계정을 권장)
    - 페이스북 페이지를 하나 만들고 그 인스타그램 계정을 페이지에 연결
    - developers.facebook.com > 내 앱 > 앱 만들기 (유형: 비즈니스)
      > 제품에 ‘Instagram Graph API’(페이스북 로그인 방식) 추가
    - 도구 > Graph API 탐색기에서 이 앱을 고르고 권한
      instagram_basic, pages_show_list, pages_read_engagement 로
      사용자 토큰 생성
    - 같은 탐색기에서  me/accounts?fields=instagram_business_account
      를 실행하면 나오는 instagram_business_account 의 id 가 IG_USER_ID
    - 토큰은 짧게 만료되므로 장기 토큰(60일)으로 바꾸거나, 비즈니스
      설정 > 시스템 사용자에서 만료 없는 토큰을 만들어 IG_ACCESS_TOKEN 에
      넣습니다(자동 수집에는 시스템 사용자 토큰을 권장). 60일 토큰을 쓰면
      만료 전에 새 토큰으로 Secret 을 바꿔야 합니다.
    - 해시태그 검색이 권한 오류로 막히면 앱 검수에서
      ‘Instagram Public Content Access’ 기능을 신청해야 할 수 있습니다.
    해시태그는 config.json 의 instagram_hashtags 에 # 없이 적습니다.
    알아둘 제한: 7일 동안 서로 다른 해시태그 30개까지, 최근 24시간 게시물
    중 일부(표본)만 옵니다, 나이·성별은 주지 않습니다. 그래서 절대량이
    아니라 ‘같은 해시태그 안에서 시간에 따라 늘었는가’로만 해석하세요.

 ⑤ X — 유료 (이름: X_BEARER_TOKEN)
    X 개발자 포털에서 게시물 수 조회(counts)가 되는 유료 이용이 필요합니다.
    검색식은 config.json 의 x_queries 에 적습니다.

 ※ 이 수집기가 하지 않는 것은 8장에 적었습니다.

4. 화면 사용법
----------------------------------------------------------------
 맨 위 오른쪽
   장소 / 기간(24시간~60일) 선택, ‘지금 새로고침’(자료 즉시 다시 읽기)

 처음 열었을 때 (자료가 없을 때)
   ‘처음 오셨나요?’ 안내가 뜹니다. 먼저 둘러보기(데모) / 자동 수집
   연결하기(작동 구조와 연결 순서) / 받아 둔 자료 열기 중에서 고릅니다.

 자료 연결 상태 (항상 표시)
   자료원마다 마지막 관측 시각과 경과 시간을 막대로 보여 줍니다.
   막대가 짧고 초록이면 최신, 주황은 지연, 빨강은 오래됨·자료 없음.
   막대 속 눈금은 정상 갱신 주기입니다. 수집기가 실패하면 그 이유가
   빨간 글씨로 바로 아래에 나옵니다. 오른쪽 위에 다음 새로고침까지
   남은 시간이 표시됩니다.
   · 문제가 있는 줄에는 ‘연결 방법’/‘해결 방법’이 생기고, 누르면 그 자료만의
     설정 순서와 오류 메시지에 맞는 해결책이 펼쳐집니다.
   · 위쪽 ‘기본 연결 n/6’ 막대는 수집기 기록을 보고 설정 진행도를 스스로
     판단해 다음 할 일을 알려 줍니다. 다 끝나면 사라집니다.
   · ‘더 연결할 수 있는 자료’ 줄에는 아직 켜지 않은 선택 항목과 방법이 있습니다.
   · ‘자료는 어떻게 들어오나요?’를 누르면 작동 구조가 펼쳐집니다.
   · 수집기가 3시간 넘게 멈추면 원인과 해결법이 화면 위에 표시됩니다.
   · 그래프가 비어 있을 때도 ‘연결 방법 보기’로 해당 줄의 안내로 갑니다.

 [연결 보기]  이 프로그램의 중심 화면
   같은 시간축의 그래프 여러 개가 위아래로 놓입니다.
     검색 관심도(연령대별) → 생활인구(연령대별 추정) → 도로 평균속도
     → PM2.5(장소·도시대기·도로변) → 도로변 증분 ΔNO₂·ΔPM2.5 → 풍속
     → 검색어 기반 게시물 수(블로그 실선, 뉴스 점선, 유튜브 굵은 선)
     → 유튜브 새 영상 조회수 → 인스타그램 해시태그 → 구글 지도 새 리뷰
     → 가져온 SNS CSV → X 게시물 수   (자료가 있는 것만 나타남)
   아무 그래프에나 마우스를 올리거나 손가락으로 누르면 모든 그래프에
   같은 시각의 세로선이 생기고, 위쪽 고정 줄에 그 시각의 값이 모두
   나옵니다. 연령 색은 모든 그래프에서 같습니다
   (10대 분홍, 20대 주황, 30대 초록, 40대 파랑, 50대+ 보라, 전체 점선).
   현장 측정 기록을 넣으면 해당 시각에 주황 세로 띠가 그려집니다.
   ‘이 장소의 연결 자료 CSV 저장’ 은 도시데이터 관측 시각마다 같은 시각의
   측정소 값과 그날의 연령별 검색 지수를 한 줄로 묶어 엑셀용으로 저장합니다.

 [자동 발굴]
   위에서부터 ‘지금 추적 중인 장소 밈’(누르면 그 장소 그래프로 이동),
   ‘키워드로 찾은 장소’(밈 키워드, 찾은 경로, 풀린 장소, 블로그 급상승 배율,
   인구 확인, 상태), ‘제목에서 갑자기 늘어난 말’(장소로 풀린 말은 분홍 테두리),
   그리고 교차 확인용 ‘인구로 본 급증 장소’와 ‘구글 급상승 검색어’가 있습니다.
   장소 목록(맨 위 선택 상자)은 ‘키워드로 찾은 장소 밈’과 ‘고정 장소’로
   나뉘어 나옵니다.

 [연령별 반응]
   검색어 그룹을 고르면 연령대별 검색 정점, 상승 기울기, 방문 정점,
   방문 변화율, 지연(일), 민감도를 표로 보여 줍니다. 계산법은 6장.
   최소 3주 이상 자료가 쌓여야 의미가 생깁니다.

 [시간 × 장소]
   지표 하나를 골라 시간대(0~23시) × 장소 표로 평균을 봅니다.
   평일/주말을 나눠 볼 수 있습니다. 칸이 진할수록 큰 값입니다.

 [현장 측정]
   직접 잰 보행자·차량 수와 휴대 센서 PM2.5 를 넣으면, 같은 시각의 공공
   관측값(생활인구, 혼잡도, 도로속도, 측정소 PM2.5)을 옆에 붙이고
   전·중·후 비교표를 만듭니다. 5장 참고.
   같은 탭의 ‘SNS 게시물 수 가져오기’로 인스타그램처럼 API로 받지 못하는
   자료를 CSV로 넣으면 ‘연결 보기’에 SNS 그래프가 추가됩니다.
   열: time(2026-10-10 14:00 또는 날짜만), place, platform, count, keyword

 [설정]
   자료 위치, 새로고침 간격, 자료원별 성공/실패 기록, 장소 설정 확인.
   ‘자료 파일 직접 열기’로 다른 곳에서 받은 history.json 을 열 수도
   있습니다(이 경우 자동 새로고침은 멈춥니다).

5. 현장 측정 기록(CSV) 넣기
----------------------------------------------------------------
 ‘현장 측정’ 탭 → ‘양식 CSV 저장’ 으로 양식을 받아 엑셀에서 채운 뒤
 CSV(쉼표로 분리, UTF-8)로 저장해 불러옵니다. 붙여넣기도 됩니다.

 열 이름 (첫 줄, 영문 그대로)
   date         날짜 2026-10-10
   site         장소 id 또는 이름 (worldcup, 서울숲, 월드컵공원 모두 인식)
   phase        전 / 중 / 후
   slot         T1 ~ T4
   start        슬롯 시작 시각 16:40
   rep          반복 번호 1, 2, 3
   pedestrians  5분 보행자 수
   vehicles     5분 차량 수
   pm25_sensor  휴대 센서 PM2.5 (㎍/㎥)
   note         메모 (선택)

 같은 날짜·장소·단계·슬롯의 반복값을 묶어 중앙값과 범위(최대−최소)를
 계산합니다. 공공 관측값은 슬롯 시작 15분 뒤에 가장 가까운 도시데이터
 관측(±40분 이내)과 같은 시각의 측정소 1시간값(±70분 이내)을 붙입니다.
 불러온 기록은 그 브라우저에만 보관되므로 원본 CSV 는 따로 보관하세요.

6. 지표 계산 방법
----------------------------------------------------------------
 생활인구         (최소 + 최대) ÷ 2
 연령별 추정 인구 생활인구 × 해당 연령 비율 ÷ 100
                  (10대 = 10대 비율, 50대+ = 50·60·70대 비율 합. 0~9세 제외)
 도로변 증분      같은 시각 도로변 측정소 − 도시대기 측정소
                  ΔNO₂ 는 ppb 단위(ppm × 1000). 넓은 지역의 배경 농도와
                  국외 유입이 빠지므로 지역 교통 기여를 보는 지표입니다.
                  NO₂ 가 교통에 더 민감하므로 1차 지표로 보는 것을 권합니다.
 검색 정점        선택 기간(최소 3주) 안에서 지수가 가장 높은 날
 상승 기울기      정점 전 7일간 하루 평균 증가량
 방문 정점        검색 정점 3일 전 ~ 14일 뒤 사이, 해당 연령 추정 인구의
                  일평균이 가장 높은 날
 방문 변화        방문 정점의 일평균 ÷ 기준선 − 1 (기준선 = 기간 첫 7일의 중앙값)
 지연             방문 정점 − 검색 정점 (일)
 민감도           방문 변화(%) ÷ 검색 증가(%)

7. 장소·검색어·측정소 바꾸기 (collector/config.json)
----------------------------------------------------------------
 ※ 장소를 따로 적지 않아도 됩니다. 추적 장소는 keyword_discovery 가 밈
   키워드에서 스스로 추립니다. places 에는 현장 실험지처럼 밈과 상관없이
   항상 볼 곳만 적습니다(기본: 서울숲, 월드컵공원).

 keyword_discovery  밈 키워드 → 장소 발굴 설정 (3-1장)
   seed_keywords    꼭 추적할 밈 키워드 (예: "하늘공원 억새")
   seed_queries     밈을 찾을 때 쓰는 검색어 (핫플, 팝업스토어 등)
   event_words      이 말이 들어가면 행사로 보고 제외
   stopwords_extra  후보에서 뺄 말 (엉뚱한 곳으로 풀리는 말)
   rise_threshold / score_threshold  급상승 기준 배율 (기본 2)
   min_hits         추적에 필요한 포착 횟수 (기본 2),  instant_rise 한 번에 추적할 배율
   auto_track_max   동시에 추적할 최대 장소 수 (기본 8)
   resolve_max      한 번에 새로 장소를 찾아볼 키워드 수 (호출량 조절)
 places        고정 장소 목록
   id            영문 짧은 이름 (화면·CSV 에서 쓰임, 바꾸지 않는 것이 좋음)
   label         화면에 보일 이름
   citydata_area 서울 도시데이터 장소명 — 주요 장소 목록 xlsx 와 똑같이
   air_urban     에어코리아 도시대기 측정소 이름 (예: 성동구, 마포구)
   air_roadside  에어코리아 도로변 측정소 이름 (없으면 "" 로 비움)
 discovery     자동 발굴 설정
   enabled 켜기/끄기, scan_every_hours 스캔 간격, ratio_threshold 후보 배율,
   min_pop 최소 인구, min_hits 자동 추적에 필요한 포착 횟수,
   auto_track_max 자동 추적 최대 장소 수, place_words 급상승 검색어에서
   찾을 장소 관련 단어
 keyword_groups  검색어 그룹 (그룹당 검색어 최대 20개)
   name          그룹 이름,  place  연결할 장소 id,  keywords  검색어 목록
 x_queries     X 검색식 (X 인증키가 있을 때만 사용)
 search_days   검색 추이를 받을 기간(일),   search_refresh_hours  갱신 간격
 keep_days     보관 기간(일),   full_resolution_days  원래 간격으로 둘 기간

 ※ 기본값의 장소명과 측정소 이름은 예시입니다. 처음 수집 후 ‘자료 연결
   상태’에 빨간 메시지가 뜨면 이름을 목록과 대조해 고치세요.
   측정소 이름은 에어코리아 누리집 > 측정소 정보에서 확인합니다.
 ※ JSON 은 쉼표·따옴표 하나만 틀려도 수집기가 멈춥니다. 고친 뒤
   python collector/collect.py --check 로 확인하면 안전합니다.

8. 알아둘 한계
----------------------------------------------------------------
 - 자동으로 긁어 오는 범위: 서울 주요 장소 전체의 인구·혼잡·행사,
   구글 급상승 검색어, 추적 장소의 도로·날씨·대기, 에어코리아 측정소,
   추적 장소 검색어의 연령별 네이버 검색 추이, 네이버 블로그·뉴스 게시물 수,
   유튜브 업로드·조회수, 인스타그램 해시태그 게시물 수, 구글 지도 리뷰 수,
   X 게시물 수. 공식 API와 공개 RSS만 씁니다.
 - 넣지 않은 방식: 로그인 상태를 흉내 내거나 차단을 우회해 인스타그램·X
   화면을 긁는 것, 구글 지도·네이버 지도 웹페이지에서 방문자 리뷰 수나
   ‘붐비는 시간’을 긁는 것. 이유는 세 가지입니다.
     1) GitHub 같은 서버 주소는 이 사이트들이 가장 먼저 막아서 며칠 안에
        수집이 끊기고, 끊긴 구간이 연구 자료의 빈칸이 됩니다.
     2) 이용약관 위반이라 쓰던 계정이 정지될 수 있습니다.
     3) 대회 심사에서 자료 수집 방법을 물었을 때 ‘공식 API, 집계값만’이라고
        답할 수 있어야 연구 윤리 문제가 생기지 않습니다.
   같은 신호를 공식 경로로 대신 잡습니다: 네이버 지도 방문 반응 → 네이버
   블로그 후기 수, 구글 지도 붐비는 시간 → 서울 도시데이터 실시간 인구와
   구글 지도 리뷰 수, 인스타그램·X → 공식 API와 CSV 가져오기.
 - 연령 정보는 어떤 SNS 도 주지 않습니다. 연령별 밈 반응의 주 자료는
   네이버 데이터랩 연령별 검색 지수와 서울 도시데이터 연령 비율입니다.
 - 네이버 검색 지수는 연령대마다 따로 최댓값을 100으로 맞춘 상대값입니다.
   연령대끼리 높이를 비교하면 안 되고 시점과 기울기를 비교해야 합니다.
   또 일 단위 자료이며 당일 값은 다음 날 확정됩니다.
 - 서울 도시데이터의 인구는 통신 자료 기반 추정 범위이고, 연령 비율은
   반올림된 값입니다.
 - 에어코리아 1시간값은 보통 정시 10~30분 뒤에 나오며, 점검 중에는 비어
   있을 수 있습니다(화면에서 선이 끊겨 보임).
 - 상관이 보여도 날씨·요일·계절이 함께 움직였을 수 있습니다. 풍속 그래프와
   평일/주말 구분을 함께 보고, 전·중·후를 같은 요일·같은 슬롯으로 짝지어
   비교하세요.
 - 이 화면은 자료 파일을 브라우저로 읽기만 합니다. 인증키는 화면에 들어가지
   않으며 GitHub Secrets 또는 내 컴퓨터의 keys.env 에만 있습니다.

9. 문제가 생겼을 때
----------------------------------------------------------------
 화면에 ‘data/data.js 파일을 읽지 못했습니다’
   → 아직 수집이 한 번도 안 된 상태입니다. 3장의 2-A 5) 또는 2-B 3) 을
     먼저 실행하세요. GitHub 주소로 열었다면 Pages 설정(2-A 6))을 확인하세요.

 ‘자료 연결 상태’에 ‘인증키 없음’
   → Secrets 이름 철자(대문자, 밑줄)나 keys.env 내용을 확인하세요.

 서울: INFO-100 / 인증키가 유효하지 않습니다
   → 키를 다시 복사하세요. 앞뒤 공백이 섞이는 경우가 많습니다.
 서울: 해당하는 데이터가 없습니다 / CITYDATA 없음
   → citydata_area 장소명이 목록과 다릅니다. xlsx 목록에서 복사해 넣으세요.

 에어코리아: SERVICE_KEY_IS_NOT_REGISTERED_ERROR
   → 신청 직후라면 1~2시간 기다리세요. 계속되면 Decoding 키로 바꿔 넣으세요.
 에어코리아: 자료 없음 (측정소 이름을 확인하세요)
   → air_urban / air_roadside 의 측정소 이름이 틀렸습니다.

 서울: 호출 한도 초과 관련 메시지 (보통 오후~밤에 발생)
   → 인증키마다 하루 호출 수가 제한됩니다. 기본 설정의 하루 사용량은
     추적 장소 × 48회 + 전체 스캔 약 120 × 8회 입니다. discovery 의
     scan_every_hours 를 6으로 늘리면 스캔 호출이 절반이 됩니다.

 주요 장소 전체 스캔: 응답한 장소가 없습니다
   → 서울 인증키 문제입니다. 위 서울 항목을 먼저 해결하세요.

 구글 급상승 검색어 오류
   → 구글이 일시적으로 막았거나 주소가 바뀐 경우입니다. 다른 자료 수집에는
     영향이 없습니다. 계속되면 discovery.enabled 는 그대로 두고 무시해도 됩니다.

 buzz 오류 HTTP 401 / 024 (네이버 블로그·뉴스)
   → 네이버 애플리케이션의 사용 API 에 ‘검색’이 추가되지 않았습니다.
 youtube 오류 HTTP 403 quotaExceeded
   → 하루 할당량 초과. social.youtube_refresh_hours 를 12로 늘리세요.
 gplaces 오류 HTTP 403 (PERMISSION_DENIED / billing)
   → Places API (New) 사용 설정과 결제 계정 연결을 확인하세요.
 instagram 오류 (#10) / (#200) 권한 오류
   → 토큰 권한(instagram_basic 등)과 IG_USER_ID 를 확인하세요. 계속되면
     앱 검수에서 Instagram Public Content Access 를 신청해야 합니다.
 instagram 오류 (#190) 토큰 만료
   → 새 토큰으로 IG_ACCESS_TOKEN Secret 을 바꾸세요(시스템 사용자 토큰 권장).

 네이버: HTTP 401
   → Client ID/Secret 이 틀렸거나 애플리케이션에 ‘데이터랩(검색어트렌드)’
     API 가 추가되지 않았습니다.
 네이버: HTTP 429
   → 하루 호출 한도 초과. search_refresh_hours 를 늘리거나 그룹 수를 줄이세요.

 GitHub Actions 가 빨간 X
   → 실패한 실행을 눌러 ‘수집’ 단계의 로그를 봅니다. ‘사이트 게시’ 단계에서
     실패했다면 3장 2-A 3) 의 Read and write 권한 설정을 확인하세요.

 그래프가 비어 있음
   → 기간을 늘려 보세요. 수집을 시작한 지 얼마 안 됐다면 자료가 적습니다.
     연령별 반응 표는 최소 3주 자료가 필요합니다.

 휴대폰에서 화면이 오래된 자료를 보여 줌
   → ‘지금 새로고침’ 을 누르세요. 다른 앱에 있다가 돌아오면 자동으로
     다시 읽습니다.
